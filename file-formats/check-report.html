Check Report (ferx check --json)

ferx check <model.ferx> [--data <data.csv>] --json emits a structured JSON report describing every validation finding, instead of the human-readable summary. The report is designed to be consumed programmatically — by editor tooling, CI, or a coding agent authoring model files — so findings carry a stable machine-readable code rather than only prose.

This is the same data the Rust API returns from validate_model_file; see also the CLI reference for the human-readable form and exit codes.

Top-level shape

{
  "valid": false,
  "model": "mymodel",
  "data": "data/mydata.csv",
  "diagnostics": [
    {
      "severity": "error",
      "code": "E_MISSING_COVARIATE",
      "message": "Model references covariate(s) not found in data (case-sensitive): WGT. Available covariate columns: (none).",
      "suggestion": "available covariate columns: (none)"
    }
  ]
}
Field Type Notes
valid bool true when there are no error-severity diagnostics (warnings alone keep it true).
model string Model file stem.
data string Present only when --data was supplied.
diagnostics array Every finding; see below. May be empty.

Diagnostic object

Field Type Notes
severity "error" | "warning" Only error affects valid and the exit code.
code string Stable identifier (see table below).
message string Human-readable description.
block string Optional. Owning model block, e.g. "error_model". Omitted when not attributable to one block.
line integer Optional. 1-based source line — see the caveat below.
suggestion string Optional. Actionable hint.

Optional fields are omitted entirely when absent (not emitted as null).

Error / warning codes

Grouped by what the finding is about. Codes are stable; new ones may be added over time. Treat an unrecognised code as a generic finding of its given severity.

The tables below list every code the engine emits — the ones ferx check reports, the ones an entry point returns as EngineError::code(), and the ones that open a message in a run’s warnings — and the in-code registry in src/diagnostics.rs lists the same set. A unit test fails when either drifts from the codes in src/ (#1051).

Model-file structure

The file could not be read as a ferx model at all, or names a block ferx does not have.

[fit_options] and [error_model] lines are consumed end to end or reported as E_PARSE with the offending line quoted. A [fit_options] line that is not a key = value pair names the repair (`method saem` is not a `key = value` pair — did you mean `method = saem`?); an [error_model] line matching no statement form lists the accepted forms. Before 0.4.0 both were dropped without a diagnostic, and the method case is the sharp one — the fit then ran the default estimator while ferx check reported the file VALID, so a run the author read as SAEM was FOCEI and its objective was not comparable to the one they asked for. See #1390, Fit options and Error model.

Code Severity Meaning
E_PARSE error The model file failed to parse (catch-all for parser errors).
E_MODEL_READ error The model file could not be read: it does not exist, cannot be opened, or is not UTF-8. The message names the path and the operating system’s reason, and no block is set. Before #1752 this was reported as E_PARSE. The check reads the file once, and parses and binds that one read, so a file moved or edited while the check runs does not change its result.
E_FIT_OPTION error A call-time fit-option override handed to validate_model_file_with() could not be applied: the key is not a [fit_options] / [data_selection] key, or its value is one the key does not accept. One diagnostic per pair, no block; like a parse failure it is terminal, so the report carries only these (#2165). A model file’s own [fit_options] refuses the same values at parse time as E_PARSE.
E_MISSING_BLOCK error A required [block] is absent. block names which one. run_model_simulate() (ferx --simulate) returns it on block simulation for a model file with no [simulation] block (#1788).
E_UNKNOWN_BLOCK error A [block] header is not a recognised block name. The message lists every offending header with its line, the valid set this build accepts, and a did-you-mean when there is a near match; suggestion carries the near match on its own. See #1040.
E_DEPRECATED_BLOCK error A [block] that was ferx syntax and is no longer read — currently [initial_values], whose contents moved inline into [parameters]. Reported separately from E_UNKNOWN_BLOCK so the message can name the replacement instead of offering a did-you-mean that does not exist.
E_BLOCK_INSTANCE_NAME error A [block NAME] instance name is given for a block that takes none (e.g. [fit_options DOSE]), or omitted for one that requires it ([covariate_nn NAME]).
E_BLOCK_FEATURE_DISABLED error A recognised block needs a cargo feature this binary was not built with — [event_model] / [binary_model] need --features survival, [markov_model] needs --features markov. ([covariate_nn] has its own E_NN_FEATURE_DISABLED.)
E_NN_FEATURE_DISABLED error A [covariate_nn] block requires building with --features nn.
W_PARSE warning A warning the parser recorded while building the model that has no dedicated code. ferx check reports it under W_PARSE with the parser’s own message, which names the block involved. fit() reports the same text in FitResult.warnings.
W_DATA_PATH_OVERRIDE warning A data path was passed explicitly (--data, or from R) and the model file’s [data] block names a different file — compared as written, then as canonicalized paths. The explicit path is used.

Parameters and random effects

A theta, eta, kappa or sigma the model uses is not declared, is declared in the wrong order, or has no data to bind to.

A [parameters] line must also be consumed end to end by exactly one declaration form, at both ends: text before or after a complete declaration is reported as E_PARSE with the offending line quoted, and so is a line matching no form at all. The one shape with a code of its own is a scale tag on a block_* declaration, below. Before 0.4.0 all of it was dropped without a diagnostic — including leading text, which could silently turn block_sigma PROP ~ 0.04 into a diagonal sigma.

Code Severity Meaning
E_ETA_NOT_DECLARED error An unresolved identifier reads as a random effect (ETA… / KAPPA…) but no omega / kappa declaration defines it, and the data carries no such column. Usually a deleted omega line whose exp(ETA_…) term was left behind.
W_ETA_NOT_DECLARED warning As E_ETA_NOT_DECLARED, but reported without --data, where ferx cannot yet know whether the dataset supplies the column.
E_SIGMA_ORDER_MISMATCH error A single-endpoint [error_model] names its sigmas in an order other than the [parameters] declaration order. These sigmas are consumed positionally, so the written names must match the declared order. Fix by reordering the sigma declarations (permuting a block_sigma’s lower triangle with them) — reordering the arguments also parses but swaps the proportional and additive roles, i.e. changes the model. See #1001 and Error model.
E_BLOCK_VARIANCE_ONLY error A scale tag ((sd), (variance) or (var)) on a block_omega, block_sigma or block_kappa declaration. The lower triangle mixes variances and covariances, so one tag cannot say which entry is on which scale. The repair depends on the tag, and the report’s suggestion carries whichever applies: after (sd), square each SD into a variance and write the off-diagonals as covariances; after (variance) or (var), delete the tag - the lower triangle was already on that scale, so the tag said nothing and nothing else needs changing. The code is raised only when deleting the tag leaves a declaration that parses, so the repair is always sufficient; a tag alongside other stray text is E_PARSE. Until 0.4.0 the tag was dropped in silence and the file reported VALID, so an SD-coded block fitted from squared-wrong initial estimates. See #1377 and Parameters.
E_IOV_MISSING_OCC error Model declares kappa (IOV) parameters but no occasion labels were found. Set iov_column to read them from a dataset column, or iov_occasion = dose / time(...) to derive them in the model, both in [fit_options]. On --simulate the [simulation] design has no dataset and gives each subject a single dose, so the message names only iov_occasion = time(...), with a breakpoint inside the times grid. It says that iov_occasion = dose derives a single occasion there, and that an iov_column the model sets has no effect (#2005). Not raised for a model with nested levels, whose groups come from its level columns.
W_IOV_OCC_MISSING warning Some rows in the IOV occasion column had missing or unparseable values; those rows were assigned occasion=0.
E_THETA_LEVEL_BINDING error A theta NAME[COL, ...] level block could not be bound to the data’s levels: a level column missing or non-finite, no observation rows, or a contrast the data cannot carry. Block parameters. The binders return the same code from a running program, where it also covers binding to a fit’s level layout (a level the fit estimated no θ for), which ferx check cannot reach.
E_COVARIATE_STATS_BINDING error A [covariate_model] statistic could not be bound to the data: a levels = auto relation whose data carry one level, or a covariate with no non-missing value. Block covariate_model. The binders return the same code, including for a fit’s statistics that do not match the model.

Priors, weights and unused parameters

A declared parameter that nothing reads, a prior that names no parameter, or a kappa weight or initial estimate the data make unusable.

Code Severity Meaning
E_PRIOR_UNRESOLVED error A declared prior cannot be applied: it names no theta / omega / sigma / kappa in [parameters], names a FIXed parameter, an element of a block_omega / block_sigma / block_kappa, or a name that resolves to several coordinates; it is declared twice; its central value is not finite (or not positive for a log-packed parameter); or a [priors] from_fit was not expanded. The message names the parameter.
W_UNUSED_PARAM warning A user-declared θ, ω or κ is not referenced by any [individual_parameters] or [event_model] expression, or a σ is not referenced in [error_model]. It does not affect predictions and is not meaningfully estimated. Generated θ (NN weights, diffusion) and the iiv_on_ruv η are not checked.
E_KAPPA_WEIGHT_NONPOSITIVE error A kappa NAME ~ value weight = W sample-size weight evaluates to zero, a negative number or a non-finite value at some observation or dose record, at the model’s initial θ. κ is applied as κ/√W, so such a weight divides an individual parameter by zero. The usual cause is a missing or non-numeric cell in the covariate the weight reads. The first offending record is reported.
W_KAPPA_WEIGHT_VARIES_WITHIN_OCCASION warning A weighted kappa’s weight expression evaluates to different values (relative difference above 1e-9) at two observation records of the same occasion, or of the same group of the kappa’s level when nested levels are declared. κ is drawn once per occasion or group, so its effective variance Ω_IOV/W is ambiguous; each record is scaled by its own weight. Reported once per kappa, naming the first subject.
W_ADDITIVE_INIT_SCALE warning A combined error model’s additive SD initial estimate is below 1% of the data scale (the median abs(DV) of the observations that endpoint covers). From such a start a multimodal fit can settle where the additive term collapses and the proportional one inflates. The value is not changed; if the fit converges with the additive variance near zero, retry from about 10% of the median abs(DV).

Covariate statistics and level blocks

A [covariate_model] statistic or a theta NAME[...] level block that has to be bound to the data, and the data it is bound to.

Code Severity Meaning
E_COVSTAT_UNRESOLVED error A [covariate_model] relation still needs statistics derived from the data — center = median, levels = auto, or a form whose default bounds come from the data — and none were bound. Reported with --data, where the binding was attempted.
W_COVSTAT_UNBOUND warning As E_COVSTAT_UNRESOLVED, but reported without a --data file: the model is fine, it just cannot be built until a dataset supplies the statistics.
E_COV_LEVEL_UNKNOWN error The data carry a value of a categorical [covariate_model] covariate that is not one of the relation’s levels, which the generated factor would silently model as the reference level (#1111, #1740). Raised by fit(), ferx check, the simulate*, adaptive and predict* entry points, compute_npde_npd, run_sir and run_covariance.
E_THETA_GATHER_INDEX_MISSING error A theta NAME[...] block gathered by a bare data column, where some observation or dose record of a subject has no value in that column. Every record that reads the block needs one. Reported at most once per block and subject.
E_THETA_GATHER_INDEX_RANGE error A theta NAME[...] block’s index column holds a value on some record that is not finite, not a whole number, or outside 1..=N for the block’s N levels. The index is 1-based — a 0-based column is the usual cause — or theta NAME[N] declares too few levels. Reported at most once per block and subject.
E_THETA_LEVELS_DATA_UNBOUND error A model whose theta NAME[...] level block is bound was handed a population never bound for it, so no record carries an index into the block’s levels — the usual “fit, then predict or simulate new data” without binding the new data. The message names the binder to call (bind_from_fit after a fit, bind_theta_levels on a fresh parse), or “k of n subjects” and the first such ID when only some subjects carry the index (#1647, #1762). Raised by fit() and the predict*, simulate*, adaptive, NPDE and post-hoc entry points.
E_THETA_LEVELS_DATA_MISMATCH error A population that carries a bound level block’s index was bound for other levels than the model’s (#1762): a record’s index is not the position, in the model’s level table, of the label its own level columns spell, or an index arrives without its level column. Unseen labels are listed, or the first misindexed record is named. Refused, never re-indexed. Raised by the same entry points as E_THETA_LEVELS_DATA_UNBOUND.

Residual correlation

A residual correlation line, or a block_sigma correlated residual, against the rows it correlates.

Code Severity Meaning
E_RESIDUAL_CORRELATION_RANGE error The θ behind a residual correlation <kind>(RHO) by … line can leave the residual covariance R indefinite: a cs ρ at or below −1/(n−1) for the largest block of n rows, a negative car1 ρ, or a fixed / simulated value with abs(ρ) ≥ 1. A free ρ must also be bounded within ±0.995, since R becomes numerically singular as abs(ρ) approaches 1; FIX it to hold a value closer to ±1.
E_RESIDUAL_CORRELATION_RESET error Under a residual correlation ar1(…) or car1(…) line, one block holds rows on both sides of a TIME reset (an EVID=3/4 record that restarts TIME), so their order and the lag between them are undefined. Add the occasion column to by so each occasion is its own block, or use cs.
E_RESIDUAL_CORRELATION_TIES error Under a residual correlation ar1(…) or car1(…) line, two rows of one block share a TIME. ar1 orders a block by TIME, so tied rows have no order; car1 correlates them by ρ^0 = 1, which makes R singular. Give them distinct times or use cs.
W_RESIDUAL_CORRELATION_INERT warning The model declares a serial residual correlation line, but in every subject each block formed by its by column(s) holds at most one observation. No two rows are correlated, so ρ does not enter the likelihood and cannot be estimated. Check that the by columns group the rows meant to be correlated.
W_BLOCK_SIGMA_L2_ORDER warning Some subjects with no L2 grouping id have a (time, occasion) group in which one observation shares a block_sigma correlation with two or more others, so the cross covariances are paired one-to-one in CSV row order and reordering rows would change the fit. Add an explicit L2 column giving each correlated unit its own id.
W_L2_UNUSED warning The data carry an L2 column, which the reader always treats as the reserved level-2 grouping id for block_sigma pairing, but the model declares no correlated residual. The column therefore does nothing and is not readable as a covariate; rename it if a covariate was meant.

Profiled level blocks

A level block declared profile (#1065) has its levels solved for at every outer step rather than searched by the optimizer. That needs a linear route to the prediction and a least-squares objective, so the check refuses anything else; nothing falls back to ordinary estimation.

Code Severity Meaning
E_PROFILE_SCOPE error A profiled block that cannot be fitted that way: profile on a single θ, with FIX or with bounds; a method other than foce / focei, or n_agq > 1; a non-Gaussian endpoint; a residual error that is not additive, or log-transformed; M3 censoring; a correlation line (not yet); a [mixture], [diffusion] or FREM model; covariance_method = s or rsr; optimizer = trust_region or mma; global_search; a parameter prior. Block parameters.
E_PROFILE_NOT_LINEAR error A profiled block that a prediction does not read as c × block plus terms that do not read it, with c from the data alone. The message names the construct (a function, power, remainder or inline if, an if branch, a second read, a parameter coefficient, a divisor, the states, the residual error, a second profiled block) and where it is, or says that no prediction reads the block. Block parameters.

Nested variability levels

A model that declares level lines (nested levels, #1082) is checked for how its levels are declared and whether the data can identify them.

Code Severity Meaning
E_LEVEL_MIXED_WITH_IOV_COLUMN error A level declaration together with iov_column or iov_occasion in [fit_options], an iov_occasion rule other than column in the fit options or SimulateOptions of a model with nested levels (block fit_options), or a kappa with no at LEVEL in a model that declares levels. A level replaces the occasion options, and once levels exist every kappa names its own. Block parameters.
E_LEVEL_MISSING_LABEL error A record (observation, dose, EVID=2 / MDV=1 row or reset) has no numeric value in a level column (a blank cell is missing, not carried forward from the row before; a text label such as NCT01 has to be written as a numeric code). Its group at each level is identified by its labels from the outermost level down, so every record needs all of them. The message names the level, the column, the record and its time. Raised by the fit, ferx check --data and every simulate* entry point. Block parameters.
E_LEVEL_SINGLE_MEMBER error A level has at most one group inside every group of its parent, and one of its kappas enters the model through the same parameters as a random effect of the parent level (the subject’s η for the first level). The two variances cannot be told apart. A level where some parents hold several groups is not refused. Block parameters.
W_LEVEL_SUMMARY warning Informational, not a finding: one row per level of a model with nested levels, outermost first, e.g. level `ARM`: 7 groups in 3 `STUDY` groups (per `STUDY` group: min 1, median 2, max 4); 1 of 3 `STUDY` groups holds a single `ARM` group; 1 kappa at `ARM` (K_ARM). Counted on the observation records. The parent of the first level is the subject. E_LEVEL_SINGLE_MEMBER refuses a level only when every parent holds a single group and a kappa has a twin; a level where some parents hold one group and others several is identified and fits, and this row is where its count shows. Counted on the observation records, as the refusal counts them; a parent with no observation record is left out. Not reported while a level label is missing (E_LEVEL_MISSING_LABEL). Raised by ferx check --data only, not recorded by fit() (#2035). Block parameters.
E_RESIDUAL_CORRELATION_GROUPING_AMBIGUOUS error A residual correlation … by line on a model with nested levels whose grouping a level and a data column would read two ways: a level name inside a list of columns (by (STUDY, ARM)), a level name that is also a different data column, or the by column of a level nested in another level written under another name. by L naming a level groups by that level’s groups, nested by key; a column groups by its value within ID, which merges two groups that share a label in different parents. The message names the level and says what to write. Raised by the fit, ferx check --data and simulate(). Block error_model.
E_RESIDUAL_CORRELATION_CONFOUNDED_KAPPA error A correlation cs(…) by … line whose blocks group the observation rows exactly as the groups of a level that carries a kappa (a nested level, or the occasions of a one-level model), compared as partitions in every subject, so cs by ARMID beside kappa … at ARM counts. A kappa gives each group’s rows one shared random effect, which is the correlation cs estimates: ρ and the kappa variance are not identified together. ar1 and car1 are not refused, and neither is cs over a grouping no kappa is at. Block error_model.
W_RESIDUAL_CORRELATION_PARTLY_CONFOUNDED_KAPPA warning The same comparison holds in some subjects but not all, e.g. cs by STUDY next to a kappa at ARM where some studies have one arm. The model is identified, from the other subjects, and fits; the message gives the count, since ρ and the kappa variance are separated by those subjects alone. A subject whose partitions agree only trivially (every row its own block, e.g. one observation) counts on neither side, here or for the refusal. Raised by the fit and ferx check --data.

Initial estimates against the optimizer box

Every initial estimate is packed and compared against the box the optimizer will search inside, before the first objective evaluation. All of the codes below are data-independent, so ferx check model.ferx reports them without a --data file. The two that are not skipped when maxiter = 0 are called out where they appear; for the rest the exemption is because an evaluation-only run clamps the start like any other, it just does not hold the clamped value through a search.

Against the box the optimizer searches
Code Severity Meaning
E_OMEGA_INIT_AT_RAIL error A free omega / kappa / [mixture] omega(k) variance whose initial value packs onto the optimizer’s -6 lower rail — every variance ≤ 6.1e-6, and ~ 0.0 in particular (a declared zero is regularised to 1e-8, packing to ln(L) = -9.21). The start is clamped onto the rail and the coordinate cannot be estimated from there: it stays collapsed or runs away to the opposite rail, moving the θ estimates with it. Either FIX it (that is the supported way to declare no variability) or start it at ≥ 1e-5. NM-TRAN rejects the same stream with error 76, INITIAL ESTIMATE OF VARIANCE CANNOT BE ZERO UNLESS FIXED. Σ is not included — a free sigma ~ 0.0 (sd) is clamped onto its own -8 rail and recovers the optimum. Only reported when an optimizer will actually search: maxiter = 0 (NONMEM MAXEVAL=0, as used by ferx gam --no-fit) is not reported — it clamps the start like any other run, but produces one objective and stops, so nothing is trapped on the rail; note that it therefore evaluates a free ~ 0.0 at exp(-12) rather than at the declared value, which FIX avoids. saem / imp / impmap / bayes carry their own iteration counts and are still checked. A model used only with predict() / simulate() is not exempt on the check path: ferx check reports what fit() would refuse, so such a model is reported here while still simulating fine. Add maxiter = 0 to [fit_options] if the file is genuinely simulation-only. The message is chosen per eta, not per matrix: an eta declared inside a block_omega / block_kappa is told its block is near-singular (in a block it is the correlations that drive L_ii to zero, so raising a declared variance is not the fix), while a diagonally declared one is told to write ~ 0.0 FIX. Mixing a block and diagonal omega lines in the same model — the whole Ω then packs as one Cholesky — does not change what the diagonal eta is told. A one-eta block_omega (NAME) = [...] is correlated with nothing, so it gets the declared-zero explanation rather than the near-singular one, spelled in its own form (write `block_omega (NAME) = [0.0] FIX`) (#1394). See #1229 and Parameters.
E_THETA_INIT_OUTSIDE_BOUNDS error A theta whose initial value is strictly outside its own declared range. The optimizer clamps the start into its box, so theta TVCL(0.05, 0.1, 10.0) fits from 0.1 — a factor of two — silently, on every run. NM-TRAN refuses the identical stream before any estimation (error 24). Judged against the declared numbers, not the packed ones: theta TVCL(-5.0, 0.0, 10.0) is reported even though -5 and the declared lower 0 both pack onto the same 1e-10 floor, and the message names where the fit really begins (1e-10, which is neither the declared value nor the declared bound). A start exactly on a bound is not reported: there the clamp is a no-op, so nothing moves. Shares E_OMEGA_INIT_AT_RAIL’s maxiter = 0 exemption. See #1251.
W_INIT_OUTSIDE_BOUNDS warning An initial estimate strictly outside one of ferx’s internal rails rather than a declared bound: the hidden 1e9 θ cap, the Ω ±6 (variance ≤ 1.6e5) / off-diagonal ±10 guards, or the Σ [-8, 5] guard. Clamped there before the first objective evaluation. Warnings a simulate* call (or compute_npde_npd_diag, which simulates its reference distribution) returns in its warnings, prefixed with the code. The simulation still completes.

Code Severity Meaning
W_IOV_NO_OCCASIONS warning The model declares kappa (IOV) parameters and an Ω_IOV is supplied, but some subjects carry no occasion label once iov_occasion has been applied. Those subjects get no κ draw and are simulated (or, from compute_npde_npd_diag, have their NPDE/NPD reference distribution simulated) at κ = 0. Silent when no Ω_IOV is supplied.
W_FREM_DRAWN_ETA warning A FREM model was simulated with each subject’s η drawn from Ω, covariate η included: by simulate_with_options_diag() without match_method, by simulate_with_uncertainty_diag(), or by an adaptive simulation for the subjects with no supplied η. A FREM model links its covariates to the PK only through Ω, so those subjects’ PK follows the drawn covariate η, not their own covariate values, and their FREMTYPE rows report the drawn covariate value. Silent on a non-FREM model (#2245).
W_SIMULATED_FLIP_FLOP warning On a transit or inverse-Gaussian absorption closed form with no ODE twin, some simulated individuals with a positive dose before their last observation were evaluated at a sampled η inside the flip-flop regime (or the 2-cpt confluent-eigenvalue corner). There the closed form clamps the dose-driven concentration to zero, so their rows carry no contribution from their doses and still enter every summary. The message gives the count out of the eligible individuals; rewrite the model as an explicit ODE to simulate them. W_UNCERTAINTY_DRAWS_SKIPPED warning Some parameter draws of simulate_with_uncertainty put a transit or inverse-Gaussian closed form with no ODE twin into the flip-flop regime at typical values, where it has no solution, so those draws were not simulated. W_RTTE_DEGENERATE warning While simulating a repeated-event (RTTE) stream, a subject’s expected number of events before the horizon is non-finite or exceeds 1,000,000, so the stream is skipped; or a stream that passed that check produced more than 1,000,000 events, so it is truncated. Either way the subject is censored at the horizon and the rest of the population still simulates. Check the hazard parameters and covariate values.
W_TTE_DEGENERATE_HAZARD warning While simulating a time-to-event endpoint with an analytic hazard, a subject drew a non-positive or non-finite effective hazard rate. No event is generated and the subject is censored at the observation window. Under competing risks it is raised for each analytic cause whose draw degenerated when the subject ends censored. Check the hazard parameters and covariate values.

Adaptive dosing

simulate_adaptive() and simulate_adaptive_from_spec() refuse most of these before any subject is simulated. The rest come from the driver once it runs, when they depend on the resolved doses, the break timeline or what the controller returned (#1983).

Code Severity Meaning
E_ADAPTIVE_UNSUPPORTED error A model the adaptive-dosing driver cannot simulate faithfully (no [odes] block, an SDE, a covariate-selected [error_model], a residual correlation line, a log-transformed (LTBS) error model — #2129), an auc_target on a subject with a time-varying covariate, IOV or a reset, or a pre-scheduled base regimen with an EVID=3/4 reset under a time-varying covariate or IOV, refused before any subject is simulated. Once the driver runs (#1983): a base dose under a time-varying covariate or IOV that is not a plain bolus or infusion into a plain compartment, a dose lag or infusion duration that is not finite, or an [odes] right-hand side that reads TAD / TAFD before any dose. The block is the one at fault, when there is one.
E_ADAPTIVE_OPTIONS error AdaptiveSimulateOptions with no usable schedule (decision_times empty, not finite, not strictly increasing, or longer than max_decisions), a monitor on a compartment the model does not have, a Dv monitor on a compartment no [error_model] covers, or decision_times / monitors set alongside an [adaptive_dosing] spec that owns them. These are refused before any subject is simulated. Once the driver runs (#1983): two of a subject’s times (decision, observation, EVID=2, reset or base-dose) within 1e-15 of each other without being equal, which the driver cannot tell apart.
E_ADAPTIVE_CONTROLLER_ACTION error The controller returned an action the driver refuses (#1983): a dose into compartment 0 or one past the model’s states, an amount that is negative or not finite, an infusion rate that is not positive and finite, a dose into a compartment fed by a built-in input-rate function or carrying a lag, or a Stop followed by another action. The controller is the caller’s code, so this is a refusal of the input, although only a simulation can reach it. On simulate_adaptive_from_spec() the controller is compiled from the spec’s route, so the same refusal is E_ADAPTIVE_SPEC there. A non-finite amount computed from a diverged ODE state is not this code: the driver refuses a non-finite state, or a monitor that reads a non-finite value, before the controller runs, as an uncoded runtime error naming the states or the monitor (#1578).
E_ADAPTIVE_SPEC error An [adaptive_dosing] spec that does not compile against the model: an invariant the block parser checks (on a spec built in code), an assay_cmt out of range or with no [error_model] to draw the assay from, a route compartment out of range or fed by a built-in input-rate function, or an observe expression that does not compile. From simulate_adaptive_with_inputs / simulate_adaptive_from_spec_with_inputs, before any subject runs: a [mixture] model (the run carries no mixture class, so a fit’s η̂ would be simulated under class 1), η names that are not the model’s in the model’s order, or a simulated subject with no supplied η under UnmatchedSubjects::Refuse (the default), listing up to ten IDs. Post-hoc steps on a fit

run_sir() and run_covariance() take a fit, and refuse one whose inputs they cannot recover or verify (#1774). ferx check has no fit, so it raises none of these. simulate_with_uncertainty() also rebuilds a fit’s parameters, and refuses a [mixture] fit’s override values with the same two codes. It draws from the fit’s covariance matrix (asymptotic method) or its kept SIR resamples, and refuses one the fit does not carry, or an empty pool, as E_FIT_INPUT_MISSING, and one that is not the size of the model’s packed parameters as E_FIT_INPUT_MODEL (#2044).

Code Severity Meaning
E_FIT_INPUT_MISSING error An input the step needs was neither passed nor recorded on the fit: the model file’s path (no model passed), the data file’s path (no population passed), SIR’s covariance matrix, the population of an IOV model passed as a model on a fit that records no reader settings, the occasion rule of an IOV fit saved before ferx recorded one, on a population that carries no occasion labels, or the fitted values of a [mixture] fit’s per-class overrides, on a fit that records neither them (mixture_overrides) nor a packed estimate holding them.
E_FIT_INPUT_CHANGED error The model or data file the step re-reads no longer has the SHA-256 the fit recorded.
E_FIT_INPUT_MODEL error The model the step would run on is not the one the fit was made with: a model passed in bound with other data-derived bindings than the fit’s, a model passed in whose covariate statistics the population does not reproduce (on a fit that records no bindings), a model whose η count is not the width of the fit’s per-subject η̂, a [mixture] fit whose recorded override values are malformed, or which records none and whose packed estimate has another layout or no longer reproduces its reported estimates, or a covariance matrix that is not the size of the model’s packed parameters.
E_SIR_OPTIONS error SIR settings run_sir() cannot run with: sir_resamples above sir_samples, a sir_df that is not a valid Student-t degrees of freedom, or sir_scale = natural on a model with prior(...). A sir_df below 1 is refused as [fit_options] refuses it, and is refused by fit() and ferx check up front whenever sir = true or covariance_fallback = sir (#1770); otherwise fit() with sir = true reports the same text as a SIR failed: warning instead.
E_SIR_NOTHING_TO_SAMPLE error every estimated parameter of the fit is FIX (θ, Ω and σ, and Ω_IOV, block_sigma correlations and [mixture] overrides where the model has them), so run_sir() has nothing to sample. Block parameters. fit() with sir = true reports the same text as a SIR failed: warning instead.
E_ODE_SOLVER_OPTIONS error ODE solver settings on a FitOptions built in code that no solver can run with: an ode_reltol or ode_abstol that is not finite and positive, ode_max_steps = 0 (#2044), or ode_stiff_abort_after = Some(0), which [fit_options] spells as off (#1770). Refused on an analytic model too, since every fit records these settings. Raised by fit(), run_sir() and run_covariance(); run_sir_core() returns the same text as a String. A model file’s [fit_options] never gets this far: the parser refuses the same values as E_PARSE.
E_LOGIT_THETA_OUT_OF_RANGE error A free θ used as inv_logit(logit(θ) + ETA) whose estimate is not strictly inside (0, 1), so it has no logit-scale draw (#2044). Only a declared upper bound above 1 lets the estimate get there; the suggestion is to declare one below 1 and refit. Block parameters. Raised by simulate_with_uncertainty() with the asymptotic method and by run_sir(). Its to_string() ends with the suggestion; run_sir_core() returns that text as a String, and fit() with sir = true reports it as a SIR failed: warning.

The θ count and the Ω, σ and ΩIOV shape of a fit against the model are E_THETA_LENGTH and E_PARAM_SHAPE, the codes every entry point gives a parameter vector of the wrong shape. A population that is not the fit’s is E_POPULATION_MISMATCH, or E_FIT_SUBJECTS_MISMATCH when the fit’s per-subject rows are what is wrong.

When the step re-reads the model or data file, a failure is the one ferx check reports on the same file, with the same code and block: E_MODEL_READ, the parse codes, E_DATA, E_MISSING_COVARIATE, E_COVARIATE_NOT_NUMERIC, and E_PARSE on data_selection for a recorded selection clause that no longer compiles. The message is the read’s own: an E_DATA refusal has no Failed to read data file lead.

Line-number caveat

line is currently block-level: when present it points at the [block] header that owns the finding, not the exact offending token or column. A finding that is not attributable to a single block (for example a missing-covariate error, where the reference may appear in several blocks) omits line. A missing required block omits line too, since the block has no header in the source. Token/column-level spans are a possible future enhancement.
