- **An `EVID=2` or `EVID=0, MDV=1` row now starts the clock** (#1809). NONMEM starts each
  subject's system at its first record of any type. The reader dropped an `EVID=2` row on a
  subject whose covariates were all constant, and an `EVID=0, MDV=1` row on every subject. So
  an `[odes]` model whose state moves before the first observation (a production term,
  `TIME` in the right-hand side, an `init()` that is not an equilibrium) integrated from the
  first observation or dose, with no warning. The first observation then read the initial
  state, and every later one inherited the missing window. Whether a subject was affected
  also depended on whether some unrelated column happened to vary within it. Predictions,
  objectives and estimates change on such datasets, and now match NONMEM 7.6.0. The same
  rows now also start the hazard clock of an ODE-accumulated `[event_model]` hazard.
  Analytical models are unaffected, except IOV models (below), and so is the SDE/EKF
  objective, which still starts at the first observation or dose. **IOV models:** such a row
  inside an occasion is evaluated with κ = 0, not under its own `OCC`, so the interval
  ending at it integrates without the occasion's κ. That limitation predates this change,
  but it used to reach only subjects with a column that varies within the subject; it now
  reaches every subject with such a row. On `warfarin_iov`, one such row per occasion
  raises the OFV by 3.6. See the IOV page's Limitations. Since the reader builds a different subject from the same
  file, the population-fingerprint scheme is bumped: re-reading a `.fitrx` written before
  this change warns that the fingerprint is absent, rather than reporting a population
  mismatch. On a pure-TTE analytical model such a row no longer re-enables the
  dose-compartment check.
